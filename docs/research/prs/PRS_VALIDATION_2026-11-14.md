## 二、全部癌症方向：查核證據與決策

### 權重來源已接上，HR 方向仍待資料

本次從 PGS Catalog 取得 PGS004875 原始檔，與已固定 SHA256 的 GRCh38 harmonized 檔逐列比較。818,872 列中的 rsID、effect allele、other allele 與 effect weight 都相同。因此這次 harmonization 沒有把整個分數變號。這項結果不能回溯證明作者在產生 HR 表前是否另改過權重、分數或標籤。

接著讀取作者 repo 固定 commit `179986db2f9af3b6eb32e4e16dc9201a23d2a29c` 的公開程式：

- [`GeneratePRS.sh`](https://github.com/intervene-EU-H2020/flagship/blob/179986db2f9af3b6eb32e4e16dc9201a23d2a29c/PRS/GeneratePRS.sh)以 PLINK 加總，沒有寫出全部癌症專用的分數取負號。
- [`PRSSummationOverChr.R`](https://github.com/intervene-EU-H2020/flagship/blob/179986db2f9af3b6eb32e4e16dc9201a23d2a29c/PRS/PRSSummationOverChr.R)累加各染色體的 `SCORE1_SUM`，沒有翻轉符號。
- [`HazardRatio_AgeStratified.R`](https://github.com/intervene-EU-H2020/flagship/blob/179986db2f9af3b6eb32e4e16dc9201a23d2a29c/PRS/HazardRatio_AgeStratified.R)讀入該分數，以遞增 quantile／cut 建組，40–60% 為參考，再做 Cox 分析。公開程式未解釋目前全部癌症表格為何需要鏡射標籤。

這些程式是公開流程模板，並不是 EstBB 執行時的完整可追溯輸入／輸出。PGS Catalog 的 cohort 效能仍有正負方向不同的紀錄，也不能從中挑一個數字直接結案。[官方效能表](https://www.pgscatalog.org/score/PGS004875/)

本次另以 PGS ID 與模型全名查找公開驗證來源，尚未取得能補齊這段實際輸入鏈的獨立資料；這不是證明其他資料不存在。

目前平台與來源的對應為：

| 平台分組 | 目前讀取的來源標籤 |
|---|---|
| <20 | >80% |
| 20–40 | 60–80% |
| 40–60 | 40–60%，HR=1 |
| 60–80 | 20–40% |
| 80–90 | 10–20% |
| 90–95 | 5–10% |
| ≥95 | <5% |

機器可讀的四年齡層 HR 對照另存 [cancer_hr_mapping.csv](validation_20261114/cancer_hr_mapping.csv)，每列均標為 `INFERRED_NOT_DIRECTION_VALIDATED`。原文曲線重現仍成立，但不能將這個重現當成權重→疾病方向的獨立證據。

**本次決策：方向對應尚未結案，保留原計算以供研究追溯，UI 與報告明示待確認。** 沒有自行反轉全部癌症的權重、改 HR 或宣告高／低分組已驗證。

### 能讓這件事往前走的資料

需要作者實際的 AllCancers 權重／score 定義與分組輸出，確認是否曾取負號、換模型或重標籤；或取得使用同一 PGS、方向明確、有疾病終點的獨立驗證資料。具體待確認問題是：

1. EstBB 該份 HR CSV 對應哪一份 AllCancers 權重及哪個計分／標準化版本？
2. 分組前有無對分數取負號？若有，是所有 cohort 或只有部分 cohort？
3. 公開表與論文的標籤鏡射，原因是權重方向、分組輸出還是其他處理？可否提供修正版／映射證據？
4. 是否可提供方向已釐清的同一 PGS 外部效能資料，以及其病例定義與共變項？

本次沒有對外寄信。癌症間分數相關與個別位點檢查仍只能作輔助。

## 四、共用驗證工具與追溯已實作

新入口為 `python3 -m research.prs.validation`，提供四個子命令：

- `sources`：固定來源 hash、回文計數與全部癌症原始／harmonized 對照。
- `model`：對照原始 PGS 與院內保留模型的座標、allele、beta、位點數；統計 REF effect、complement 及保留回文。
- `benchmark`：從另一份單樣本 VCF 的明確基因型及原始權重獨立加總，套用個案缺失遮罩，比較原補值與 EAS 頻率，量分數／標準差／百分位／跨組差異；可與平台 summary 對帳。
- `aggregate`：彙整同版本比較結果，列完整／部分覆蓋、位移與跨組次數；不把重複樣本／遮罩數稱為人口數。

benchmark 不把 VCF 中沒有出現的位點當成 0/0。真值未覆蓋全部保留位點時，標為 `PARTIAL_TRUTH_COVERAGE`，不產生全模型百分位或數值通過宣告。計分路徑不匯入平台的基因型重建／加總函式；保留集合與頻率仍是明確共享輸入，不能稱為疾病 outcome 驗證。

新工作另產生 `provenance.score.json`、`provenance.ancestry.json`，保存可觀察到的 caller header、工具／程式／容器證據；讀不到就記未知。來源 gVCF 不做一次昂貴的全檔 hash，而沿用既有 fingerprint；原始權重及固定模型已有 hash。Nextflow 容器清單僅涵蓋當次 Log 能取得的 image 路徑，未取得不等於沒有使用其他容器。這些檔案隨結果發布到既有 08 artifacts，未為舊工作倒填資訊。

完整指令、輸入要求與限制見[離線驗證操作文件](../../ops/PRS_VALIDATION.md)。目前缺院內模型／真值／遮罩，沒有用合成資料的測試結果代替真實六病敏感度結果。

## 五、UI 與健檢報告現在怎麼呈現？

| 情境 | 呈現 |
|---|---|
| 靠近七分組邊界 | 提醒排名小幅變動可能跨組；不稱為信賴區間 |
| 該疾病／性別／實際期間的七組累積風險有逆轉 | 指出相鄰組未依百分位遞增，不能解讀為高 PRS 有保護作用 |
| 全部癌症 | 明示權重與 HR 分組方向仍待確認，研究性重建不作已確認高風險解讀 |
| AF 的期間全在 `[20,30)` 來源零值區間 | 表格顯示「來源零值*」，附「來源資料在此年齡設為零，無法據此確認零風險」 |
| AF 的期間部分跨過零值區間 | 保留完整期間的數字，說明前段資料限制；30 歲後仍照模型計算 |
| 評估起點的曲線值為零 | 顯示「評估起點」，避免當成未來零風險 |
| 非零但四捨五入為零 | UI 顯示 `<0.01%`、報告顯示 `<0.1%`，門檻只來自各自顯示精度 |
| 已患病／病史不明／QC 不足／期間不適用 | 保留原原因，AF 提醒不覆蓋這些狀態 |

提示由同一份伺服器呈現邏輯產生，讀的是當次評估快照綁定的參數。API 額外回傳 `presentation`；原始 `inputs`、`result` 與快照檔不因此重寫。報告以同一邏輯產生文字，重複提醒合併列出疾病名稱。

舊評估重新載入／重新匯出即可看到新文字；缺少二十年結果的舊快照仍須按原規則重新計算。新工具追溯只在新分析工作產生，程式 fingerprint 改變時會使用新 run，不碰舊已發布結果。
