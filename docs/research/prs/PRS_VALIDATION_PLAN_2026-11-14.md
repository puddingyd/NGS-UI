# PRS 三項後續工作計畫

日期：2026-11-14｜狀態：**規劃，尚未執行驗證或平台修改**｜起始程式基線：`2d4d634`。

本計畫接續 [Claude 的審查](reviews/PRS_REVIEW_2026-11-13.md)及[我們的回應](PRS_REVIEW_RESPONSE_2026-11-14.md)，只處理使用者選定的三項：全部癌症方向、六病計分／補值／來源追溯、風險跳動與 AF 零值的呈現。文件版本關係見[審查索引](README.md)。

這一輪先把現有方法的證據補齊，並準備可審閱的 UI／報告文字。不在本輪更換 EAS735、重估台灣 HR、啟用 BBJ、替換 GBD 或強制平滑分組 HR。

## 一、全部癌症的權重方向與 HR 分組對應

### 要回答什麼？

我們現在加總得到的 PGS004875 分數，究竟是作者 HR 分析中哪一個方向的分數？平台目前的七分組，是否真的接到同一方向、同一參考組的 HR？

原文曲線可以重現，證明的是 HR 與已發表曲線的對應；還要證明「實際使用的權重→分數方向→分組→HR」整條鏈。這是本輪第一優先，先於任何調整全部癌症權重或分組。

### 規劃的工作

1. **整理來源鏈。** 固定 PGS004875 原始權重與 GRCh38 harmonized 檔、作者計分／標準化／分組程式、EstBB 原始 HR 表、論文分組定義、效能資料及目前 `CANCER_SOURCE_GROUPS`。每個環節記來源、日期、hash、分數定義與參考組；缺原始檔就明記缺口。
2. **對照可能的符號轉換。** 檢查作者是否對整個分數取負號、重新定義高低組、改用另一種 PRS，或只有輸出標籤相反。把「來源標籤」「實際分數範圍」「來源 HR」「平台目標組」排成一張表。加總時 REF effect allele 的 `2−dosage`／offset，是等位計算問題，不能與整個模型取負號混為一談。
3. **用獨立計分核對分數。** 使用原始權重及經核對的基因型，與作者或另一條計分路徑比較，確認平台算的是同一個方向的數值。此步可驗證計分對應，但沒有疾病 outcome 時，不能單獨證明發病風險方向。
4. **補方向與疾病的獨立證據。** 優先尋找使用同一權重／方向且有明確疾病終點的獨立效能結果；若需要有 outcome 的個體資料，先記取得條件。只有現有健檢基因型、沒有可靠癌症資料時，不能宣稱完成這一項。若來源鏈仍缺關鍵環節，整理需向作者確認的具體問題，由使用者決定對外聯繫。
5. **輔助排查。** 全部癌症與乳癌分數的相關、已知位點方向、不同 cohort 的效應正負可用來找矛盾，但都不作唯一通過依據。資料間若有訓練／驗證重疊，也須標明。

### 交付與結案方式

交付一份方向對照表、來源索引與結論紀錄。結論分開寫：

- **計分方向是否已對上：** 原始權重與平台分數的符號／等位對應是否確認。
- **HR 分組是否已對上：** 作者分析用的分數與各組 HR 是否有可查證的連結。
- **獨立疾病證據到哪裡：** 哪些 cohort／終點支持、哪些仍有衝突或缺資料。

能結案的依據是來源可追溯、對應可重現，且獨立證據的適用性已說清楚；「224 筆曲線通過」或「兩癌相關為正」不單獨通過。若缺關鍵作者資料或 outcome，結果標為**待資料**，不反覆試符號直到圖看起來合理。若確認現行對應錯誤，另提出明確修正、影響範圍及舊結果處理方案。

對照位置：`research/prs/absolute_risk/build_multi.py`、`registry.py`、`research/prs/multidisease/prepare.py`、`run.py`，以及固定來源與風險包。來源事實與推論分開記錄。

## 二、六疾病的獨立計分基準、補值敏感度與追溯

### 2.1 先建立共同驗證框架

六病共用一套驗證資料、重建與彙整框架，每個疾病輸出自己的結果。驗證分成三層，避免全部都只是在重算同一份中間檔：

| 層次 | 比較方法 | 要抓到的問題 |
|---|---|---|
| 位點與權重 | 從原始 PGS 重新核對座標、REF／ALT、effect allele、權重與納入／排除原因 | 共用模型準備步驟的方向錯誤或漏列 |
| 計分 | 原始權重＋經核對基因型的另一條加總路徑，對照平台固定模型與 PLINK | REF effect、符號、offset、缺失平均補值與加總錯誤 |
| 端到端 | 有獨立基因型基準的公開樣本，從院內 DRAGEN gVCF 經平台完整六病流程 | caller、reference block、品質篩選、重建及格式轉換造成的差異 |

另一條計分路徑不能直接拿平台產出的 `weights.tsv` 或 `models.sqlite` 當作唯一真值，否則仍會共用準備階段的錯誤。獨立基準本身的格式、等位處理與限制也要記錄。

先確認可取得哪些公開基準樣本、對應的院內 gVCF 與實際 reference 成員；不要預設某個常用樣本一定在目前 3,330 人內。盡量涵蓋東亞樣本及不同批次／品質。比較完整分數前，先在共同且可靠的基因型範圍比較，再把差異拆成：基因型不同、品質門檻、缺失補值、未涵蓋位點與其他原因。基準未涵蓋的區域不能當成平台錯誤，也不能直接當成正確。

### 2.2 補值敏感度怎麼做？

1. **先固定其他條件。** 保持權重、位點集合、重建規則與風險參數相同，離線比較目前 3,330 人頻率補值與 EAS735 頻率補值。
2. **使用實際缺失型態。** 從既有個案的 audit／`missing_loci.tsv.gz` 取得缺失遮罩，在具有可靠基因型的參考者上模擬同樣的缺失；另外涵蓋不同缺失率及高影響位點缺失。參考者本身缺失與頻率估計的相依性要標明，必要時使用留一法或獨立頻率估計。
3. **比較影響。** 每病列完整基因型與遮罩後的分數差、相對該病參考標準差的偏移、百分位位移、七組重分類率及最大／尾部影響；分開看靠近分組邊界的個案。
4. **分辨兩種問題。** 先用現有 ECDF 量「只改補值」的影響，標為敏感度試算。若要正式提出新補值方法，另檢查參考者缺失與重建分布，建立相容的新 ECDF／模型版本；不能新分數繼續冒用舊模型名稱。
5. **再討論 QC。** 缺失位點數與目前 `abs(weight)≥0.001` 提醒，與上述實測結果一起看。忽略 LD 的變異貢獻近似只作輔助；本輪不先指定任意新 gate。先提出規則，再用未參與規則制定的資料檢查，避免只挑對目前樣本有利的門檻。

### 2.3 回文位點怎麼記錄？

五個新增疾病來源檔的零回文結果，沿用 2026-11-14 回應中的已完成查核，補入正式驗證紀錄，記檔案 hash、列數、判定規則及查核日期。這次規劃不把它重新宣稱為新實驗。

CHD 要補核對兩層：原始權重檔，以及院內凍結的 610,305 位點 master。若也為零，即記錄並結案；若存在，才規劃在同一固定基準下的排除敏感度。屆時除整體分數相關外，也看尾部排名、分組與個案差異，不以相關係數單一門檻通過。沒有回文不等於所有等位方向都已驗證。

### 2.4 caller 與工具追溯要保存什麼？

| 類別 | 規劃保存內容 |
|---|---|
| gVCF | 來源識別／fingerprint、樣本身分、組裝、header 中的 caller／版本及可取得的產生設定；無法確認者明記未知，不從檔名猜版本 |
| 科學模型與資料 | 六病原始 PGS／固定模型／reference／補值頻率的版本與 hash，FASTA、dbSNP 及原始 HR／風險包的識別 |
| 實際執行工具 | 該工作環境中實際使用的 bcftools、samtools、PLINK、Nextflow、Apptainer／Singularity 版本；pipeline commit、容器 hash、重要套件與參數 |
| 執行證據 | 程式 commit、日期、步驟、命令參數、退出狀態、輸出 hash、可用的原始 Log 位置及驗證摘要 |

先整理哪些欄位已存在、哪些須新增，再提出最小的 provenance 補強。來源及工具從實際執行環境取得；缺失不能補成推測值。若新增 metadata 會影響 cache／resume 或快照相容性，要一併訂清楚；舊個案不得被補寫成彷彿當時已收集這些資訊。

目前驗證範圍以 DRAGEN hard-filtered gVCF 為主，其他 caller 另建設定與基準；不為了讓它通過而全面接受 `FILTER=.`。

### 2.5 需要的資料與交付

| 資料 | 目前狀態／後續取得方式 |
|---|---|
| 原始五病權重、來源索引、HR／風險包、程式 | repo 及先前本機快取可供整理；依 hash 核對版本 |
| CHD 原始權重與凍結 master | 需核對院內 `original_scorefile`、`method2_model_dir`／lock 實際指向 |
| 六病模型與參考基因型／分數 | 需院內 `multi_model_dir` 的 manifest、`models.sqlite`、`reference_scores.json`、PGEN／頻率及校準結果 |
| 缺失 audit 與來源資訊 | 由既有 PRS case work／正式發布 artifacts 讀取；以去識別彙整結果記錄 |
| 獨立公開基準樣本與配對 DRAGEN gVCF | 先確認是否已存在；沒有時列為需準備資料，不能用一般個案取代真值 |

大型資料留院內，未來可準備唯讀稽核／離線比較入口，將彙整結果帶回。這份計畫本身不執行院內命令。

交付六病各自的驗證表，以及共同的方法與資料索引。結果區分「數值一致」「差異已有原因」「未解釋差異」「待資料」。可沿用現有加總對帳的 `1e−5` 作數值一致性檢查，但這不是等位正確、排名穩定或臨床準確的通過標準；端到端差異須回到基因型與缺失原因解釋。

對照位置：`research/prs/multidisease/{prepare,reconstruction,run,common}.py`、`research/prs/scoring_v211/method2_score.py`、`backend/app/workers/prs_run.py` 與 `backend/app/services/prs_paths.py`。規劃一套共用驗證框架，避免六病各造一套工具。

## 三、風險跳動與 AF 零值的 UI／報告文字

### 3.1 分開說明三種現象

| 現象 | 造成的解讀問題 | 規劃呈現方式 |
|---|---|---|
| 百分位接近組界 | 小幅排名變動就可能跨組，風險跟著跳動 | 個案接近組界時提示；目前 2 百分點旗標只作提醒，不能稱為 95% 誤差範圍 |
| 來源 HR 有非單調估計 | 某些情境下，高百分位組的估計風險反而略低 | 方法／限制說明七組來源估計有雜訊；若做個別提示，要按該疾病、性別與實際期間判定，不能把任何年齡的 HR 逆轉套到所有輸出 |
| AF 年輕區間基準設為零 | 數字可能讓人誤以為年輕人不會發病 | 根據評估期間是否涵蓋來源零值區間，顯示專屬文字；保留跨到非零區間的實際計算 |

先處理說明與對應的呈現規則。顯示相鄰組風險若要納入，需標為「分組敏感度比較」，不能叫信賴區間；這一輪不把七組 HR 平滑成新的連續模型。

### 3.2 可審閱的文字草案

**一般百分位說明（UI 方法區與報告定義）：**

> PRS 百分位表示這個分數在參考族群中的排名，不是發病機率。風險依七個百分位區間估算，因此排名小幅變動、跨到另一個區間時，風險數字可能出現跳動。部分區間的相對風險估計受研究樣本與統計誤差影響，百分位較高不保證每一組的估計風險都較高。

**接近組界時的個案提示：**

> 此百分位接近風險分組邊界；排名小幅變動就可能改分組，風險數字也可能改變。這是分組穩定性提醒，不是個人風險的誤差區間。

**非單調的補充說明：**

> 此疾病的部分相鄰組估計值沒有依百分位依序增加。這反映來源研究估計的限制，不能解讀為較高 PRS 對疾病有保護作用。

**AF 期間全部落在來源零值區間時：**

> 來源資料在此年齡設為零，無法據此確認零風險。

**AF 期間部分涵蓋來源零值區間時：**

> 本次評估期間有部分年齡使用來源資料設定的零發生率，估計受此限制；其餘年齡仍依模型計算。這不代表零值年齡不會發病。

上述都是草案，正式套用時按情境選取，避免每個疾病重複一大段文字。

### 3.3 AF 的具體顯示規則

以當次快照所綁定的參數與實際評估期間判定；目前來源的年輕零值範圍為 `[20,30)`。不能只看評估年齡、疾病名稱，或看到四捨五入後 `0.00%` 就套提示。

| 情境 | 規劃的 UI／報告行為 |
|---|---|
| 評估期間全部位於已確認的來源零值區間 | 該風險欄以「來源零值，無法確認零風險」等短文字取代裸露的 `0%`，並附完整說明；原始模型數值仍保留在可追溯結果中 |
| 評估期間同時涵蓋零值與非零區間 | 保留整段實際計算的風險數值，附部分期間受限的說明；不把整欄改成無法計算，也不只截取 30 歲後冒稱完整期間 |
| 評估期間完全不含來源零值區間 | 正常顯示該期間數值，不加年輕零值提示 |
| 圖形上的平坦零值片段 | 在圖註／可存取的資料說明中標示該片段的來源限制；後續非零曲線照實呈現 |
| 已患病、病史未確認、QC 未通過或期間超出模型 | 沿用相應的不可評估原因，不能被 AF 零值文字覆蓋 |
| 非零數字四捨五入成 0.00%／0.0% | 與來源設零分開處理，不冒稱來源零值；可依顯示精度採「<…%」，門檻與格式需明列 |

例如 20→30 歲全部位於來源零值區間；25→35 歲則跨入非零區間。相同個案的十年、二十年與至 80 歲風險，可能因此需要不同提示。判定必須對每個輸出期間分別執行，並核對 30 歲邊界。

### 3.4 會放在哪裡、如何確認一致？

- **UI：** 維持現有六病表格與六張曲線，在相關儲存格／疾病列／圖註放短提示，方法與限制區放完整解釋。一般提醒不擴成新的頁籤。
- **健檢報告：** 表格使用短文字或標記，在相鄰的結果說明補完整文字；依先前的細明體、固定 tab 定位及欄寬檢查換行與分頁。
- **共用呈現邏輯：** 由同一份語意規則產生 UI 與 DOCX 提示，讀取當次評估使用的參數及期間；必要的新 metadata 另訂相容方式，不回寫舊快照。
- **驗收：** 涵蓋零值全段／部分／不涵蓋、年齡邊界、非零但被四捨五入為零、不同風險期間與不可評估狀態，並確認 UI 與匯出報告使用相同原因。

對照位置：`backend/app/services/prs_presentation.py`、`prs_multi.py`、`frontend/prs.js`、`backend/app/report_content/prs_chd_v1.json`、`backend/app/services/docx_export.py`。風險積分本身仍由 `research/prs/absolute_risk/engine.py` 負責；呈現文案不能偷偷改數值。

## 四、順序、交付與決策

| 順序 | 工作 | 完成後可決定什麼 |
|---|---|---|
| 1 | 全部癌症來源鏈＋六病可用資料盤點 | 哪些能直接驗、哪些須院內資料或作者確認；癌症方向還缺哪一段證據 |
| 2 | 六病獨立計分與缺失敏感度；回文與工具追溯紀錄 | 差異來源、需要補強的 QC，以及有無具體計分修正必要 |
| 3 | 依查核結果定稿 UI／報告呈現規則及文案 | 哪些提醒應普遍說明、哪些須針對個案期間顯示 |
| 4 | 另經使用者同意後實作與驗收 | 實際平台變更、版本與影響；若要改科學模型則另列決策 |

文字草案可與來源盤點同步準備；涉及全部癌症「高分代表高風險」的正式敘述，須等方向查核有足夠證據。外部資料缺件不妨礙其他疾病的計分驗證及 AF 呈現規劃，但不能把缺件項標成通過。
